# Changelog

All notable changes to `@motifx/core`, `@motifx/compiler` and `@motifx-community/skills`. The three packages move together: one version number, one entry.

## 1.2.0

### Migration notes from 1.1.0

- **Lifecycle hooks are camelCase only.** Components and compiled output use `onBuilt`, `onInitialized`, `onVisibilityChanged` and the other camelCase names; the lower-case spellings are no longer recognised.
- **A DOM event handler that returns `false` no longer cancels the event.** Return `{ cancel: true }` (or use the `:prevent` / `:stop` modifiers) to call `preventDefault` and `stopPropagation`.
- **Development mode and devtools are switched on only through `app.useDevelopment(true)`**; a hand-set `__MOTIF_DEV__` global is not read. Devtools live on the `__MOTIF_DEVTOOLS__` object; the devtools contract, `registerDevtools` and the `MotifDevtools` types are exported from `@motifx/core/devtools`.
- **The Vite plugin's hidden `//useReact` and `//useVue` skip comments are gone.** Use the `exclude` option (`string | RegExp | (id) => boolean`) to leave files out of the compiler.
- **`FromService(token)` is typed `T | null`.** It already returned `null` with the `MJX414` warning when nothing was registered; under `strict` write `FromService(X)!` when you know the service is registered, or check for `null`. `inject`, `provider.get` and `provider.getAsync` keep their non-null types and throw instead.
- **`onVisibilityChanged` receives the new visibility state** as its argument.
- **Props are no longer copied into `motif.options`**; read them from `this.props`.
- **Every hidden or waiting component leaves a position trace** (a comment node) in the DOM so it can return to its place.
- **`app.dispose()` is awaitable**; it disposes the `run()` shell and the application services after the component tree.
- **Navigation scrolls instantly between pages** and keeps the hash in history mode.
- **`scrollMemory` no longer writes to `sessionStorage`**; the `persist` option is gone. Positions live in memory, survive `restartRouter()` and are lost on reload. To keep them across reloads, save them with `app.router.saveScrollPositions(fn)` (called whenever saving is due) and put them back with `app.router.restoreScrollPositions(positions)`; `app.router.scrollPositions()` reads them.
- The esbuild `jsx` setting is no longer part of the setup instructions; the compiler plugin alone configures JSX.
- **`doWork(promise)` is typed `Promise<T | MotifError>`.** Once the component is disposed it resolves to a `MotifError` (`MJX108`); a rejection that arrives after disposal resolves the same way, with the rejection as `cause`, instead of reaching `catch`. Check `instanceof Error` before using the value; code that used the value unchecked no longer compiles.
- **`onMounted` hooks run after the current task**, in small batches, so a page with many of them does not freeze. Work that does not need the element in the document belongs in `onBuilt`.
- **`onMounted` follows the component tree.** The hook runs once the component sits under a root that is in a document, with every component on the way visible; the root is the `run()` host or a component that wraps an element already in the page. An element put into the document by hand with `appendChild` no longer mounts: wrap the target with `new Component(element)` and give it the content with `controls.add`.
- **A route change does not wait for the leaving page to be disposed.** The router removes the leaving page (after its own leave transition, when it has one), mounts the new page and disposes the leaving page after the new page is painted. A left page's `onDisposing` and `onDisposed` run later and see the new route, and `app.navigate` resolves before them; the page's bindings and its `context.on` / `context.onRouterChanged` subscriptions stop as it leaves, and its `scoped` services stay alive until it is disposed.

### Added

- Reactivity: `Map`, `Set`, `WeakMap` and `WeakSet` are tracked, reads and writes included; values placed in reactive collections are reactive too. `deepClone` copies `Map`, `Set`, `RegExp`, class instances and cyclic values.
- Options API: an Options object (`{ el, data, view, ctor }`) is accepted as a route component, as a `Lazy` module and in `new Component(...)`; an Options component whose `el` is a DOM node is built as a component root. `motifOptions(spec)` returns the object as it is and types `this` inside its methods as the component, so `this.class`, `this.motif` and `this.props` type-check under `strict` and complete in the editor.
- Routing: a parameter can carry a pattern and span segments: `{id(\d+)}` matches only what the pattern allows, `{path+}` takes one or more segments and `{path*}` zero or more, as plain text; rest routes sort after the others and `href`, `navigateByName` and `redirect` fill them segment by segment. `router.resolve` returns the path chain and the navigation result; `validate()` receives the route table keyed like `key`; `navigate` accepts a scroll option; path parameters are decoded and generated paths encoded, and `router.uri` keeps the address form so links match in either spelling. A route's ready component instance is kept alive across entries. Route linting adds `MJX319` (a `:` outside braces in a path or alias) and `MJX320` (a parameter pattern that cannot be used); `MJX318` reports a route entered with a disposed instance.
- Routing: `app.router.scrollPositions()`, `app.router.restoreScrollPositions(positions)` and `app.router.saveScrollPositions(fn)` read, put back and save the scroll memory's positions; the save callback is called whenever saving is due and its subscription survives `restartRouter()`.
- Events: a `:once` listener runs exactly once whichever way the event arrives; a DOM listener on a component without an element listens on its content elements (`:self`, `:once` and `off` cover all of them); event handlers are kept as light records; `motif.on('online', ...)` keeps its name.
- Components: fragments hide and show like elements; `motif.hide()` resolves after the leave transition and completes when the animation is cancelled; `moveToIndex` lands the child on the given index; children added while their owner is hidden are built; a hidden child placed before its parent is built leaves a trace; `childs` are placed by one rule (a class or Options object with `view()` places them itself, one without `view()` gets them at its root); `dom.window` falls back to `globalThis` when no window and no `setDom` DOM exist.
- Components: `x-chunk={n}` on an element, or `chunk` in its `options`, builds the element's children in slices: the first n children added together build at once, the rest leave a trace and build n per frame in order; rows of a `.map` under a chunked element are created only when their turn comes, with the index they have then. A sliced child whose build throws is reported as `MJX130`. The compiler passes `x-chunk` to the runtime and stops on a missing or non-numeric value (`MJX012`).
- Dependency injection: lookups are typed from any class token (constructor parameters, abstract classes, protected constructors); `FromService` resolves to the new navigation's scoped instance while a page is set up; a `ServiceProvider` instance in a component's provider field is the only thing treated as the service provider; a singleton registered with `startup: true` (on `@Injectable` or in the object form of `add*`) is created inside `app.run()` before the shell is built and again when `builder.rebuild()` runs while the application is running, and `MJX415` warns in development when `startup` is given to a `transient` or `scoped` registration.
- Devtools: the component tree, props, bindings, events, hooks, classes, attributes, services, DI scopes, stores, signals and computeds, effect owners and flushes, navigations with their outcome, grouped warnings and live counters are published on the devtools object; devtools can write classes, attributes, visibility, models, props, routes and store values through public APIs; community packages register extensions through `@motifx/core/devtools`; the core version is exposed as `coreVersion`.
- Devtools: the tree is a forest. `getTree([])` is an `Application` node whose children are the `run()` shell, the page layer (`Layer`) once it exists and the `host` of every window opened or attached through `app.windows` (`Window`, with the window's `title`); a path starts with the root's index, a component under no root has path `null`, and `tree:changed` reports `[]` when the root list changes. Every node tells which document holds its element (`document`, an index into `getDocuments()`, which lists the page and the connected documents; `documents:changed` reports changes). `inspect` of a window root carries `{ kind, title, open, components }`, `setVisible` refuses a root, and the contract is `version: 2`.
- Reactivity: `MJX209` warns in development when an effect tracks more than 1000 dependencies in one run, once per effect and at most ten times; with devtools on it names the owner component and binding. `useReactiveMonitor({ dependencies })` sets the limit, `0` switches it off.
- Reactivity: `MJX210` warns in development when two or more instances of the same component (or eight owner-less effects) scan the same reactive list with `find`/`findIndex`/`findLast`/`findLastIndex`/`some`/`every` and the list has at least as many items as there are scanners, wherever the list came from (props, another module, a service); once per list, at most ten times, with devtools on. `useReactiveMonitor({ scans: false })` switches it off.
- Compiler: reactive getters (JSX child and attribute getters, directives, `effect`, `createComputed`, `createLazyComputed`, `bindings.add/watch/when/ternary/switchCase`) are checked for three misuses: `MJX004` now flags a lookup by key that scans a reactive list (`find`/`findIndex`/`some`/`every` with an `x.field === value` predicate: n components cost n² reads per change; its old short-circuit advice is gone, the list itself is tracked as a whole now), `MJX017` flags a write to a reactive value the getter also reads (`++`, `+=` or an assignment to a field read elsewhere in the getter: it retriggers itself) and `MJX018` flags `sort`/`reverse` on a reactive list inside a getter, and `push`/`pop`/`shift`/`unshift`/`splice` when the getter reads that list too. Reactive roots are `this.state`, `this.props`, class fields set up with `reactive`/`useModel`/signals in an initializer or the constructor, the file's module stores and aliases of those inside the getter; callbacks of synchronous array methods (`map`, `forEach`, `reduce`, `find`…) count as part of the getter and compound predicates are followed; event handlers, reads inside `untracked(...)`, plain class fields and copies are left alone.
- Compiler: `exclude` option on the Vite plugin; `motif-explain` lists every site (`--site child|element|attr|prop|event|component-event|directive|key`) and `--json` honours `--code`; `MJX015` reports an override that does not reach `super` on every path; `MJX016` warns when a `switch` or ternary getter cannot be lowered and runs as a method; a class component hiding a `ComponentBase` member warns in development; development-only code is removed from production builds in Vite and Rollup; the element of a `Component<...>` class is declared from its type in `.ts`, `.mts` and `.cts` files; JSX is kept as written in the Vite dependency scan with Rolldown; the Vite plugin's config hook type-checks on Vite 5, 6, 7 and rolldown-vite.
- JSX types: `null` is accepted for attribute, class, style and value props; `onLeave` receives the full navigation target; DOM event handlers are typed in both arities; modifier and custom-event prop types stay on component tags so constructor props typed by an interface type-check.
- Forms: a function given to `action` on a `<form>` or to `formAction` on a button is the submit handler: it is called with the form's `FormData` after `preventDefault`, and skipped when an `onsubmit` listener prevented the event; a string stays the URL.
- Async results: `using(promise, onfulfilled?, onrejected?)` types the value from the promise and takes callbacks of any return type; a callback that throws, or an `async` one that rejects, is reported as `MJX129` with the original error as `cause`.
- Project: contributing guide, security policy and issue templates.
- Mounting: `app.run` takes a comment or text node as the host; the application is placed right before it and the node stays. `MJX416` is thrown when the node has no parent element.
- Windows: `app.connectDocument(doc)` connects a same-origin popup or iframe document; router links clicked there navigate the page's router and stack swipes work there. The connection is counted, released by the returned function, on the document's `pagehide` and by `app.dispose()`; `MJX417` is thrown for a value that is not a usable document. A component moved into another document keeps working: `class`, `attr`, the focus state, the fullscreen and pointer-lock exits, transitions and `onMounted` use the element's own document and window. A Document Picture-in-Picture window (`documentPictureInPicture.requestWindow`) is handled the same way.
- Windows: `app.windows` is a window manager. `app.windows.open(component, options)` moves a component into a new popup or, with `kind: "pip"`, into the always-on-top Picture-in-Picture window, and brings it back to its old place when the window closes; `create`, `attach`, `add`, `release`, `close`, a reactive `list`, `of`, `supports` and the `window-opened` / `window-closed` events. Stylesheets and the root attributes of the page are mirrored into the window and kept in sync; a window can follow an owner component, close on navigation or when it empties; `onClosing` runs before the window is torn down, with the reason of the close, and what it moves out is neither returned nor disposed; `returnOnClose: false` leaves the return to `orphans`; `MJX418` to `MJX423` report the misuses, `attach` on a window of another origin among them. Electron child windows and `file://` pages are covered.
- Application: `app.layer` is a component on a plain `div` placed at the end of `body`, after the `run()` host (with `body` itself as the host the layer stays last and the shell's content goes before it), for content that must sit above the page; the core gives it no styles or attributes, it can be read before `run()` (the element joins the document when `body` arrives, and comes back at the end of `body` when content next needs a place after the page removed it) and `app.dispose()` disposes it with its content. `app.layerOf(target?, ...components)` returns the layer of the document holding the target, a component or a DOM node: the `host` of a window opened or attached through `app.windows`, otherwise `app.layer`; the components given are added there, a first component with no parent and an element in no document counts as content (a root already in a document is a target), and `MJX424` is thrown for a target that is neither. `useApplication()` also returns `windows`, `layer` and `layerOf`.

### Changed

- Reactivity: reading a reactive array with `find`, `findIndex`, `findLast`, `findLastIndex`, `some`, `every`, `filter`, `map`, `forEach`, `flatMap`, `reduce`, `reduceRight`, `join`, `slice`, `includes`, `indexOf`, `lastIndexOf`, the iterators, `for...of` and spread subscribes to the array once instead of to every index; a write to an index or the length and the structural methods (`push`, `splice`, `sort`, ...) wake those readers once. A lookup that stops at a match (`find`, `findIndex`, `some`, `every`, `indexOf`, `includes`) depends only on the prefix it read: a write, an insertion or a `push` beyond the index where it stopped does not wake it; a lookup without a match and `findLast`/`findLastIndex` depend on the whole list. The items handed to the callbacks and returned by `find`, `filter`, `slice` and the iterators are reactive, as before. An effect keeps its dependencies between runs and drops only the ones it stopped reading, so the effects of a key run in the order they first subscribed.
- Performance: a component packs its state flags and creates its namespace, disposables, classes, attributes and bindings on first use; text components leave their children, classes and attributes unset until first use; a single lifecycle handler is stored without an array; static class names stay a plain string until class tracking is needed; bound lists are reordered without moving rows one by one and start with room for exactly their first entry; detached descendants and empty binding sets are skipped on dispose; the first static classes of a fresh element are written at once; the listeners of a detached child are marked removed instead of being removed one by one.
- The compiler contract stays at 1; a lone compiled setup is marked so the runtime takes it directly, and core class fields are compiled as constructor assignments.
- Enter transitions start in a microtask again; `RouterLink` builds its content in `onBuilt` and writes hrefs in the address form of the router mode.
- Core objects are marked non-reactive with a symbol instead of by constructor name.
- `Virtualization` sizes its scroll area from `totalCount` while `hasMore` is true: items not loaded yet take space below the rows (estimated from the loaded rows when `itemHeight` is a function), and scrolling into that space requests the pages in order up to it.
- Internal modules import their dependencies directly instead of through the package barrels, and `Component`, `Frame` and `Application` register themselves in a slot module, so the bundle loads in any entry order (rollup 4.61 and later sort entry modules alphabetically).
- Tooling: rollup ^4.64.12, rollup-plugin-typescript2 ^0.37, @rollup/plugin-terser ^1.0; eslint moved to devDependencies; `argparse` is pinned to 2 under `js-yaml` so the test toolchain no longer pulls in `sprintf-js`; the stale `yarn.lock` was dropped.
- A navigation scope that a component still holds (a page being disposed, a `keepAlive` page, a stack-kept page, a detached component) closes when that component has been disposed, so its `onDisposing` and `onDisposed` see live `scoped` services. The stack disposes the pages it drops after the new page is painted, and the content a left page sent with `TransportTo` leaves its slot at once.

### Fixed

- Application: a disposed application starts again with `run()`: `Application.main` is filled again, services are created anew on demand, a fresh router is built from the configuration, the `useTransitions` mode is applied again, a layer read in between moves after the host and `dispose()` runs again; `run()` throws `MJX405` when a newer application was built in between. `dispose()` called again on a disposed application releases what was created since (the layer, windows, connected documents, recreated services) without touching the address or the transition mode.
- `includes`, `indexOf` and `lastIndexOf` on a reactive array rerun an effect when an index is overwritten, not only when the length changes.
- A hidden component whose element had been moved to another document (a window of the app, an iframe) is shown where its trace was left instead of being rebuilt under its parent in the page; `MJX106` is reported only when the trace was moved or its holder left the document.
- The effect result callback is called only for a run that produced a value: a throwing getter no longer switches a `when`, ternary or `switchCase` branch (the error is still reported as `MJX208`).
- A JSX `switch` or ternary getter keeps its statements as written: locals before the switch, case bodies, fall-through and the statements after it; boolean and trailing-return branches compile; the default branch is drawn for an initial `null`; a switch slot is emptied on `null` branches; a component's own value receives `x-model`.
- The last `attr.add` for a key owns it, so an inline attribute keeps winning over a spread getter; every element of a class array is lowered like a plain class value; every class object value is the condition of its key; only the object path is guarded in equality attribute expressions; optional chaining lowers in attributes, directives and text children like the plain forms; every `x-wait` and `x-display` value reaches the runtime as a getter; a computed member key in a text child is read from its value; function values passed to directives are called; fallthrough attributes are accepted on every component tag; `srcdoc` is dropped from spread objects on DOM tags; `async` is kept on inline event handlers and `x-ref` callbacks; user bindings named `sender` or `frame` are renamed so generated parameters do not shadow them.
- A function component root binds its condition a single time (every `preconfig` hook runs once); a bound child of a component tag is placed in its `childs` slot once; a markup ternary passed as a component prop stays live in its slot; `{this.childs}` stays in its slot until the slot is built; a factory in the view that returns `null` is skipped; children given to a `Frame` are placed as its first content; argument order is kept when several children are added or inserted at an index; rows added after the first draw are built outside the list effect; every effect binding re-runs on `setState` and `reState` while an unchanged branch stays in place.
- Routing: the router token is matched inside a multi-value `rel` attribute; the `hashchange` the router causes in hash mode is ignored; history entries opened outside the router are stamped as a push so a cancelled typed address is restored; the address is reset on `app.dispose()` only in the mode the router owns; a navigation hook that throws is reported and a result is returned; a router classing callback that throws is reported and the remaining steps keep evaluating; a disposed `RouterView` is removed from the registry by instance; the navigate scroll option reaches the scroll memory container.
- Lifecycle and disposal: every lifecycle hook value is checked the same way (only what can never be called is rejected); `ref` is called after props and options are applied; `Lazy` treats disposal as silence and signals abort as `MJX111`; a missing `deep` option is treated as `true` when disposing a tree; a `Disposable` reports disposed only once; the provider skips the application and itself when disposing singletons; a `TransportTo` cancels its slot subscription on dispose; a component is not built a second time from its own build when a visibility binding shows it; `recordServiceOwner` stays synchronous; after `builder.rebuild()` components and the `ServiceProvider` token resolve from the new provider.
- Diagnostics: a class getter that throws is reported and the previous classes are kept; `MJX002` says how to give a component a callback; `MJX127` is limited to objects that are not components and reports a lazy module without a default export; a production build that strips a whole dev-only file returns the empty module; each call in a generated guard getter is evaluated once; a compiled getter that throws (a member-call child, the left side of `??` or `||`, an `&&` condition) is reported as `MJX208` and its fallback is kept; `MJX109` says the child left the content body because its content block was disposed.
- Document-level exit methods are called from method attributes, and `focus()` is called without an argument for non-object values.
- Function components get the same `key`, `ref`, common attributes, options, transition and lifecycle hooks as a class, whether they are written as a tag, with `motifComponent(fn, props)` or with `new Component(fn, props)`.
- The constructors of `Transport`, `TransportTo`, `ContentBlock` and `ContentBody` take the common component props (`childs`, `class`, `ref`, lifecycle hooks) under `strict`, as `new Component(...)` does.
- Children added to a hidden fragment, built or moved ones included, are placed when the fragment is shown; `stopAnimations()` cancels running keyframe animations and a cut leave transition completes the hide; the `style` prop of `Virtualization` is applied after the list's own root styles.
- Calling `useRouter` again while the router runs keeps the running router until `restartRouter`; a route page resolved from DI follows its lifetime: a singleton page is kept across visits and a scoped page is built once per navigation.
- `restartRouter(uri?)` starts the new router at the root, or at the given address, and replaces the current history entry instead of restarting at the old table's address. The page and layout on screen leave like a leaving page (their leave transitions play, the new page is set up after them, their cleanups run once it is on screen); a layout given as an instance or as a singleton that sits at the same place in the new table stays in place, and the route fields switch in one step after the old page is removed. Guards run on that first navigation: a redirect replaces the entry, a cancel leaves the screen empty without undoing the restart. The call returns the first navigation's result; a navigation overtaken by `restartRouter()` or `app.dispose()` resolves with `reason: 'restart'` or `'dispose'`.
- An `errorHandler` listener that throws no longer stops the listeners after it; its error is rethrown later.
- `Transporter.transport` with an `index` places the child in the new parent's element, and `transportMany` keeps the given order from that index.
- A `display` or `wait` binding set up in `initializeComponent` hides the child from the start, leaves a trace and shows the child in its place.
- Style objects and style getters write CSS custom properties (`--name`); a `null` or empty value removes one.
- The value written directly on a tag owns `value`, `checked`, `selected` and each `style` key over a spread getter, as it does for other attributes; a later `bindings.add` for one of those three replaces the earlier binding.
- `motif.on('x:initializing' | 'x:initialized')` added after construction runs the handler once.
- `mode: 'history'` on a `file:` address runs the router in hash mode and warns `MJX321` in development.
- A page shown again from the `keepAlive` cache or from a detached stack entry moves to the current navigation's `scoped` instances before `onActivated` runs, so what `onActivated` writes there is kept.
- Children disposed with their parent, and `disposeAsync()`, stop their running animations and leave without a leave transition, so an animated child no longer holds its parent or a conditional branch back.
- A page built for a navigation that a newer one overtakes is disposed instead of being kept for the next visit, so going to that route later, or to the same route with other parameters, shows a page built for the address in the bar.
- Compiler: a template string in `value`, `checked` or `selected` is live like in other attributes; a JSX element given as an attribute value without braces compiles like the braced form; a single `@DEV-ONLY` before a class member removes the member; a production build strips dev-only code from files matched by `exclude`.
